## 2. Core Principles & Architecture

### 2.1 Separation of Machine Learning and Presentation
- **The Core ML model is immutable:** The ONNX EfficientNet-B0 model weights, class indices (0 to 37), temperature scaling factor ($T = 0.413$), Shannon entropy thresholds, and canonical PlantVillage class IDs (e.g., `Tomato___Early_blight`) are **never modified or translated**.
- Canonical English labels are the permanent source of truth; regional names are looked up dynamically via the presentation layer.

### 2.2 Backward Compatibility
- All existing API endpoints (`/api/v1/analyze`, `/api/v1/diseases`, `/api/v1/history`) accept an optional `lang` query parameter or form parameter (defaulting to `en`) and respect the standard `Accept-Language` HTTP header.
- Existing JSON response payloads keep all original fields intact while appending localized crop and disease names and localized safety guidance.

## 3. Data Storage & Glossary Architecture

All multilingual content is versioned in structured JSON data files inside `backend/app/data/i18n/`:

```
backend/app/data/i18n/
├── config.json                     # System language registry and voice definitions
├── glossary/                       # Curated pathology terminology & phonetics
│   ├── en.json
│   ├── hi.json
│   ├── te.json
│   ├── ta.json
│   ├── kn.json
│   ├── ml.json
│   ├── mr.json
│   ├── bn.json
│   └── es.json
└── {lang}/
    └── diseases.json               # 38-class monographs with localized protocols
```

### 3.1 Glossary Schema (`i18n/glossary/{lang}.json`)
Each of the 38 classes contains:
- `common_name`: The term used by local farmers (in native script).
- `alt_names`: Colloquial or dialectal synonyms.
- `transliteration`: Latin-script rendering for low-literacy search and phonetic fallback.
- `scientific_name`: Binomial pathogen name (preserved without distortion).
- `tts_text`: Phonetically adjusted script optimized for neural speech clarity without robotic stumbling.
- `source`: Authoritative university extension source (ICAR, TNAU, ANGRAU, MPKV, PAU, Purdue, Cornell).
- `review_status`: `expert_reviewed` | `machine_suggested` | `draft`.

## 4. Audio Narration & TTS Architecture

### 4.1 Pluggable Provider Interface (`TTSProvider`)
AgriShield defines a pluggable provider abstraction in [backend/app/services/tts.py](file:///c:/Users/hkira/Downloads/crop-disease-detection-main/backend/app/services/tts.py):

```python
class TTSProvider(abc.ABC):
    @abc.abstractmethod
    async def synthesize(self, text: str, lang: str = "en", voice: Optional[str] = None, rate: float = 1.0) -> bytes:
        """Synthesizes text to compressed MP3 audio bytes."""
        pass
```

Supported Providers:
1. **`EdgeTTSProvider` (Default in Production):** Uses Microsoft Cognitive Services neural voices via edge-tts. High naturalness, supports all Indic regional languages, requires zero paid API keys.
2. **`MockTTSProvider` (Testing & Offline):** Generates valid synthetic MP3 frames instantly with deterministic content hashing for unit tests and disconnected CI environments.
3. **Pluggable Cloud Extensibility:** Architecture allows adding Google Cloud Neural2/Chirp TTS, Azure Cognitive Speech, or Bhashini / AI4Bharat Indic-TTS by setting environment variable `TTS_PROVIDER`.

### 4.2 Content-Addressable Audio Caching
- Generated audio is hashed by `SHA-256(clean_text + lang + voice + rate)` and cached at `backend/app/static/audio_cache/{hash}.mp3`.
- Static content (38 diseases × 9 languages × 3 sections) is pre-generated using `scripts/generate_audio.py`.
- Dynamic on-demand speech (e.g. customized weather risk summaries) is synthesized on first request and served from cache on subsequent calls.

### 4.3 Audio Narration Script Design
Audio scripts are written separately from on-screen text to optimize listening comprehension:
- Short, simple sentences designed for mobile listening in noisy field environments.
- Dosages spelled out clearly (e.g. *"दो दशमलव पांच ग्राम प्रति लीटर"* instead of *"2.5g/L"*).
- Visual emojis and technical symbols are automatically stripped to avoid robotic reading.
- Punctuation structured for natural breathing pauses.

## 5. How to Add a New Language

Adding a new language requires **zero code changes**—only configuration and data files:

1. **Register the Language in `backend/app/data/i18n/config.json`:**
   ```json
   {
     "code": "pa",
     "name": "Punjabi",
     "native_name": "ਪੰਜਾਬੀ",
     "script_direction": "ltr",
     "tts_voice": "pa-IN-OjasNeural",
     "review_status": "machine_suggested",
     "is_active": true
   }
   ```
2. **Create the Glossary File:** `backend/app/data/i18n/glossary/pa.json` with all 38 diseases.
3. **Create the Disease Database:** `backend/app/data/i18n/pa/diseases.json`.
4. **Create the Frontend UI Locale:** `frontend/src/i18n/locales/pa.json`.
5. **Pre-generate Audio:**
   ```bash
   python scripts/generate_audio.py --lang pa
   ```
6. **Validate Integrity & Parity:**
   ```bash
   pytest backend/tests/test_i18n.py -v
   ```
